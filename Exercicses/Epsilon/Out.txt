--- Machine Epsilon Calculation ---
This program computes the machine epsilon for float, double, and long double.
Machine epsilon is the smallest value such that 1.0 + epsilon != 1.0.

Computed machine epsilon values:
  float:       1.19209e-07
  double:      2.22045e-16
  long double: 1.0842e-19

Standard library epsilon values (std::numeric_limits):
  float:       1.19209e-07
  double:      2.22045e-16
  long double: 1.0842e-19

Comparing the Values:
  float:       computed = 1.19209e-07, std = 1.19209e-07 (Same!)
  double:      computed = 2.22045e-16, std = 2.22045e-16 (Same!)
  long double: computed = 1.0842e-19, std = 1.0842e-19 (Same!)

Theoretical values for IEEE formats:
  float  (2^-23):  1.19209e-07
  double (2^-52):  2.22045e-16

--- End of Calculation ---
--- Tiny Epsilon Demonstration ---
This program shows how adding very small values (less than machine epsilon) to 1.0 can behave differently depending on the order of addition.
We use epsilon = 2^-52 (double precision) and tiny = epsilon/2.

Values used:
  epsilon (2^-52):      2.2204460492503131e-16
  tiny (epsilon/2):     1.1102230246251565e-16

Computed results:
a=  1 + tiny + tiny =     1.00000000000000000
b=  tiny + tiny + 1 =     1.00000000000000022

Comparisons (using above definitions):
  a == b ?              false
  a > 1  ?              false
  b > 1  ?              true

This demonstrates that floating-point addition is not always associative when tiny values are involved.
--- End of Demonstration ---
--- Comparing Doubles Demonstration ---
This demonstrates why direct comparison of floating-point numbers can fail,
and how to use an approximate comparison instead.

d1 = 0.1+0.1+...+0.1 (8 times) = 0.79999999999999993
d2 = 8*0.1                 = 0.80000000000000004

Direct comparison (d1 == d2): false
Approximate comparison (approx(d1, d2)): true

--- End of Demonstration ---
